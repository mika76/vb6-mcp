# T18: stepping (2026-10-18, Sonnet, config B)

## The task

`tests\fixtures\Order` (written by `bench\make-order-fixture.cs`) is an order form that recalculates the whole total after every Add.

**The planted bug** (marked only in the generator):
- The helper is `LineAmount(price As Currency, qty As Long)`, so `price` is ByRef (VB's default).
- It applies the bulk discount with `price = price * 0.9`, which writes the discount back into `Prices()`.
- The first total is right. Every later recalculation discounts the bulk line again: 2 × 10 → 18.00, then 5 × 1 → 21.20 instead of 23.00, then 1 × 1 → 20.58 instead of 24.00.

**The prompt** asks for stepping: stop in the calculation, step into and over the calls, step out, watch the variables. Config B only.

**Scoring:**
- The fix is saved and builds.
- `Invoke-OrderReplay` expects 18.00, 23.00 and 24.00.
- Recorded alongside: `usedStepping` and the debugger tools used.
- Checked both ways first: the fixture replays 18.00/21.20/20.58, and a `ByVal` copy replays the expected totals.

**Stepped through by hand first.**
- Breakpoint on the `LineAmount` call in `OrderTotal`, then the second Add.
- `Prices(1)` was already 1.8. `step_into` landed in `LineAmount`; `step_over` twice, then `step_out`.
- `Prices(1)` was now 1.62.

## What it exposed, and the fixes

- **`app_set_text index` counted text boxes in window order.** On this form the locked total box comes first, so `index: 0` typed the price into the total, and the program got no price at all.
  - `index` now counts in reading order (top to bottom, then left to right).
  - `app_tree` shows each text box's `index`, and `readOnly` for a Locked one.
  - Setting a read-only box is still done, but flagged with a note, because no user could type there.
- **Step results didn't say where they stopped**, so each step needed a `debug_where`. They now carry `at`: component, line, procedure and line text.
- **`bp_toggle` refused while the program runs.** Spike 37 showed VB takes it: a breakpoint set or cleared during a run works. `bp_clear_all` doesn't work during a run (VB ignores it), so it still needs break or design mode.
